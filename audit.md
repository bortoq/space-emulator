# Аудит проекта space-emulator

Дата: 2026-10-14. Объём: код (`space.h`, `globals.c`, `config.c`,
`engine.c`, `space.c`, `bitcopy.c`), `README.md`, тесты (`tests/*.sh`),
`Makefile`. Метод: ревизия исходников, опыты, полный `make check`,
прогон ключевых сценариев под ASan/UBSan.

## 1. Найденные дефекты (исправлены в ходе аудита)

1. **`store_count`: неполный старший байт счётчика терял младший бит
   значения.** При `nfield_bits = 15` (дефолты) последний (7-битный)
   байт писался через `bitcpy(w<8)`, который копирует старшие биты
   байта, а младший бит значения сидит в не копируемой части:
   счётчик 300 читался как `2C 00` вместо `2C 01`. Нарушалось
   утверждение README «The first count byte is the low byte of the
   count». Исправлено: побитовая упаковка (бит `k` значения — позиция
   `(k/8)*8 + (7 - k%8)`) плюс обнуление неиспользуемых верхних бит.
   Код приведён в соответствие с документацией. Регрессия — опыт и
   тест «query count above 255».

Больше дефектов кода не обнаружено.

## 2. Соответствие кода и документации

Проверенные утверждения README ↔ реализация (все сошлись):

| Утверждение README | Реализация |
|---|---|
| `a = ceil(log2 space bits)`, поля `a-1`/`a`/`a`, инструкция `3a-1` | `config.c: compute_format()` |
| `-p * (3a-1) <= -s - (8 + a - 1)` (процессор плюс запись query) | `config.c: parse_config()` |
| `-p * (3a-1) <= 2^(a-1) - 1` (число загрузки в поле `n`) | там же |
| минимум `-s 26 -p 1` | `tests/cfg.sh` (приём + отказы `-s 25`, `-s 22`) |
| query: 8 бит состояния, затем счётчик `a-1` бит, низкий байт первый | `engine.c: store_count()` (после фикса §1.1) |
| query требует место вне процессора, иначе пропуск | `engine.c: query_ok()`, тест «query inside the processor» |
| бит `k` значения — позиция `k` (поля инструкций) | `engine.c: store_argument()/get_argument()` |
| первый байт потока — старший бит | `bitcopy.c` (конвенция bit 0 = 0x80) + кодировщики тестов |
| программа — последовательность тактов; такт двухфазный; запись в позиции процессора действует со следующего такта | `engine.c: computation()` |
| останов по NOP-процессору; остановочный такт не выполняется | `engine.c: computation()`, `space.c: main()` |
| неполная передача кладёт что есть, следующее обращение продолжает поток | `engine.c: space_input()/space_output()` |
| «не более одного входа и одного выхода с ненулевым `n` за такт» — норматив на программу, эмулятор не проверяет | соответствует: проверки нет, в README так и сказано |

## 3. Тесты

Покрыто (`make check`, 30 проверок): загрузка и запуск, пустой и
короткий поток, лимит тактов, останов по NOP, запросы состояния
(видимость конца ввода), битовые передачи (4 бита, позиция без
байтового выравнивания), счётчики query (полный вход 00 08,
неполный 01 08, вывод 10 00 08, счётчик >255 00 2C 01), пропуск
query внутри процессора (06), запись в `/dev/full` без зависания,
принимаемые и отказывающиеся размеры (границы минимума 25/26,
граница `-p` 697/698), дефолты (5A 5A).

Не покрыто (с оговорками):
- биты сбоя ввода/вывода состояния (`ferror`): трудно воспроизвести
  portably; код читает липкие флаги `stdio` — закрытый stdout проверен
  (`/dev/full`), закрытый stdin — частично (EOF).
- потеря байта при сбое `fwrite`: счётчик считает биты, перемещённые из
  пространства (включая потерянный байт), сбой виден по биту состояния —
  семантика допустимая, в README не расписана.
- параллельное исполнение фаз — свойство дизайна, не тестируется.

## 4. Замечания (не блокеры)

1. Пустой поток без `-t`: загрузочная инструкция не затирается, эмулятор
   вращается (правила останова). В README одной строкой не сказано —
   при следующей правке стоит добавить.
2. Проверка `-s < 8` осталась дешёвым полом; реальный минимум задаётся
   формулой (26) — так и документировано.
3. Стиль README: проза без «;», короткие предложения — проверено.

## 5. Инструменты

- `make check` — 30 проверок, все зелёные.
- `gcc -fsanitize=address,undefined` — 5 ключевых сценариев (загрузка,
   запросы состояния, EOF-запрос, счётчик 300, длинное копирование
   200 бит — длинный путь `bitcopy`) чистые, код 0.
